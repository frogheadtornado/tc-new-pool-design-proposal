Generated by `e2e/run.sh`. Do not edit by hand: run the script again to refresh it.

- **Result:** every step succeeded and every amount matched the design.

## What was done

1. `script/Deploy.s.sol` deployed the proposal on the fork: one contract. The pool did not exist yet.
2. A TORN holder with quorum locked, proposed, voted and executed the proposal through the live Governance contract. Execution used 3,677,324 gas. It deployed the 0.01 ETH pool and registered it (19 to 20 instances). It did not touch the staking contract.
3. A staker locked 10,000 TORN in Governance.
4. For each row of the table below, a user generated a new note, deposited through the Router, rebuilt the pool's Merkle tree from its events and generated a real zero-knowledge proof with the circuit and proving key of the classic UI. The withdrawal was checked by the verifier contract that is live on mainnet; nothing was mocked.
5. After the first four withdrawals, with the staking contract still the one live today, the staker claimed the TORN. The ETH fees were in the pool.
6. The later proposal, the staking upgrade (`StakingUpgradeProposal`), was deployed and passed through Governance the same way. Its execution used 2,071,877 gas: it deployed the new staking implementation and upgraded the staking contract to it.
7. Someone called `sweepProtocolFees()` on the pool, which sent the 0.00018 ETH it had kept to the staking contract.
8. One more withdrawal was made, now with the staking contract upgraded.
9. The staker claimed the ETH, then unlocked.

How to read it:

- **Registered relayer:** the user pays the relayer's fee (0.4% in this test) and nothing else. The DAO is paid once, in TORN taken from the relayer's stake and worth 0.3% of the note at the FeeManager's oracle price. The pool takes no ETH, so the relayer nets 0.1% before gas. This works with the staking contract as it is today.
- **No registered relayer:** the pool keeps 0.6% of the note (0.3% protocol fee plus 0.3% premium) for the lockers. An unregistered relayer still receives the fee the user agreed to, but burns no TORN.
- **Where the ETH goes:** the staking contract that is live today cannot take ETH. Until the staking upgrade the pool holds the fees, and nobody can take them out: the only way out is `sweepProtocolFees()`, which sends them to the staking contract and only works once it is upgraded. After the upgrade the pool pays each fee to the staking contract in the same transaction.
- The user fixes in the proof the most the pool may charge: nothing with a registered relayer, the pool fee otherwise. The table "Things that must not work" shows what happens when someone tries another path.
- Percentages are of the note. Gas is not included: the relayer pays it when there is one, the user otherwise.

## Things that must not work

| Attempt | Result |
| --- | --- |
| Someone else submits a withdrawal that names the registered relayer, through the Router | Rejected: "Only custom relayer" |
| The registered relayer sends the proof made for the relayer straight to the pool, which would charge the user the pool fee | Rejected: "Protocol fee above what the note owner accepted" |
| Someone else sends the proof made for the relayer straight to the pool, which would charge the user the pool fee | Rejected: "Protocol fee above what the note owner accepted" |
| The same note is withdrawn a second time | Rejected: "The note has been already spent" |
| Someone copies a user's proof and changes the recipient to their own address | Rejected: "Invalid withdraw proof" |
| Someone tries to forward the fees kept by the pool before the staking contract is upgraded | Rejected: "payment to STAKING_REWARDS did not go thru". The fees stay in the pool |

## Limits of this test

- The relayer is a registered relayer's address on the fork, not the relayer software. Live relayers must add the new pool addresses to their configuration before they can serve them.
- The governance vote is cast by one account given quorum on the fork. Voting delay and timelock are skipped by moving the fork's clock.
- The TORN price comes from the live oracle at the forked block, so TORN amounts differ between runs. ETH amounts do not.

## How to reproduce

```bash
# needs Foundry (forge, cast, anvil) and Node.js; a mainnet RPC URL in ETH_RPC_URL or RPC_URL,
# or in a .env file in this repository or its parent folder
./e2e/run.sh
```

The script starts the fork, deploys, runs every step above and rewrites this file. It stops at the first amount that does not match. Set `FORK_BLOCK` to fork a specific block (needs an archive RPC) and `TORNADO_KEYS_DIR` if the classic UI's `static` folder is not at `../classic-ui/static`.
